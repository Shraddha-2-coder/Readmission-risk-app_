Hospital 30-Day Readmission Risk Stratification

An industrial-style AI/ML project that estimates which discharged diabetic patients are at higher risk of being readmitted to hospital within 30 days, so a care team can prioritise follow-up calls.

Live app: https://readmission-risk-app-bgcmdmyymsw7dyjc3e6vdr.streamlit.app/

Important: the data is synthetic

The dataset (diabetic_data_synthetic.csv) was generated by code to mimic the structure of the public UCI "Diabetes 130-US Hospitals (1999-2008)" dataset. It contains no real patients. Relationships such as the effect of weight on risk were built in by the author, so the results show that the pipeline works, not clinical findings. This tool is for education and must not be used for medical decisions.

What the project does
Builds a 30-day readmission target (readmitted == "<30", about 12% positive)
Cleans the data and keeps a cleaning log (cleaning_log.csv)
Engineers features known at discharge (age, weight, comorbidity score, prior visits, emergency share, medication counts, diagnosis group)
Splits train / validation / test (60/20/20) by patient, to avoid leakage
Compares a baseline rule (2 or more inpatient visits), Logistic Regression and Random Forest (experiment_tracker.csv)
Calibrates probabilities (isotonic regression) and picks a threshold of 0.143, which flags the top 20% of patients on validation data
Explains the model with SHAP, checks fairness by gender, race and age group, and analyses missed patients
Serves the model in a Streamlit app
Results (synthetic test set, 5,915 patients)
Measure	Model (Logistic Regression)	Baseline rule
ROC-AUC	0.61	n/a
PR-AUC	0.173 (base rate about 0.12)	n/a
Recall	37.7%	19.0%
Precision	17.8%	17.8%
Share of patients flagged	25.6%	about 13%

Calibration reduced the Brier score from 0.2334 to 0.1045. The model catches about twice as many readmissions as the baseline, with the same precision, so it is a modest prioritisation tool and not a diagnosis.

App modes
Single patient: enter details and get a risk score and key reasons
Upload a file: score a CSV (up to 5,000 rows) and download a ranked follow-up queue
What-if explorer: educational mode only

Run locally
pip install -r requirements.txt
streamlit run app.py

To retrain, place diabetic_data_synthetic.csv in the same folder and run project8_readmission.py. It recreates the model files and requirements.txt.

Limitations
The data is synthetic, so the results are not clinical findings
Predictive power is modest (ROC-AUC 0.61) and precision equals the baseline rule
About 25.6% of test patients were flagged instead of the planned 20%, because tied scores after calibration sit near the threshold
Recall differs across groups (for example by age and race), so the model should prioritise follow-up and never be used to deny care
Not validated on real clinical data
